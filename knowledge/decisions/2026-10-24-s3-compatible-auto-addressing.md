# 2026-10-24 S3-Compatible Storage Auto Addressing And Checksum Posture

## Status

Accepted (2026-10-24).

## Context

The built-in `sforum.storage-s3` provider failed against Cloudflare R2:

1. aws-sdk-go-v2 `service/s3` (v1.97.x) defaults `RequestChecksumCalculation`
   to `when_supported`. Every `PutObject` then attaches a CRC32 request
   checksum (`x-amz-checksum-crc32` header for seekable bodies, `aws-chunked`
   trailer otherwise). R2 answers `400 NotImplemented`
   ("Header 'x-amz-checksum-crc32' … not implemented"). Because `Probe()`
   starts with a PutObject, both the admin draft probe and all uploads failed.
2. The SDK defaults to Virtual-host addressing. R2 only supports Path-style
   (`<bucket>.<account>.r2.cloudflarestorage.com` does not resolve). The old
   `use_path_style` boolean defaulted to `false` and its copy claimed it was a
   MinIO concern, so default-driven R2 configurations could not connect.
3. R2 documents `auto` as the region value; the field default `us-east-1`
   works in practice but was undocumented.
4. `Open()` bound the response body to the 60s operation context, truncating
   large proxied downloads.

## Decision

- Request and response checksums are configured to
  `RequestChecksumCalculationWhenRequired` /
  `ResponseChecksumValidationWhenRequired` unconditionally. This is the AWS
  recommended posture for third-party S3-compatible endpoints; AWS S3 and
  MinIO behavior is unchanged.
- `use_path_style` becomes a tri-state `auto|true|false` setting with `auto`
  as the recommended default: `auto` resolves Path-style for any configured
  non-`amazonaws.com` endpoint and Virtual-host for AWS (no endpoint or an
  explicit `amazonaws.com` endpoint). Explicit `true`/`false` (the legacy
  stored values) always win over detection.
- An empty region resolves to `auto` for R2 endpoints and stays `us-east-1`
  otherwise; explicit regions always win.
- Object read bodies are not bounded by an overall deadline. Connection,
  TLS, and response-header waits are bounded on the shared HTTP transport;
  read termination belongs to the Host RPC session `Close`. Uploads remain
  bounded (120s) to match the manifest provider timeout.

## Alternatives Considered

- Provider preset dropdown (AWS/R2/MinIO): rejected; auto detection from the
  endpoint host covers all three without an extra field.
- Global Path-style default: rejected; AWS users get correct Virtual-host
  behavior for free today and should keep it.
- Multipart or browser-direct uploads to work around large-object issues:
  out of scope per the attachments module note; single-shot PutObject with
  the Host size policy is sufficient.

## Consequences

- Existing instances storing `"true"`/`"false"` keep working; the new select
  field validates them as legal options.
- The plugin source contract and release baseline changed together
  (`1.0.10`, baseline regenerated by
  `tests/validate-builtin-plugin-versions.mjs --write`).
- Compatibility posture is asserted by unit tests on the resolved
  `s3.Client.Options()`; live R2 verification remains an operator QA step.
