# 2026-07-05 Appearance Theme Presets And Custom Color

## Decision

SForum's runtime appearance setting stores a theme choice in `web_options` as
`appearance.theme`.

Allowed values are `pine_teal`, `ocean_blue`, `violet`, `rose`, and `amber`.
The default remains `pine_teal`. The admin personalization UI also supports a
controlled custom value in the format `custom:#rrggbb`.

## Context

The existing UI used teal/green accent colors across public navigation, auth
pages, SF components, footer hover states, and the admin shell. The admin
needed a personalization entry that could change the site's visual identity.
Preset-only customization proved too narrow once admin users needed exact brand
colors and the admin shell needed to follow the same choice.

## Rationale

- Presets keep contrast and hover/soft/focus states coherent.
- A single key is simple to validate in the backend Options service.
- CSS variables can still switch the runtime look without rebuilding Nuxt.
- Custom color input stays controlled: only six-digit HEX values in
  `custom:#rrggbb` are accepted, and derived hover, soft, focus, dark, contrast,
  and primary scale variables are generated by frontend helpers.
- Nuxt UI's default `primary` color remains green unless its generated CSS
  variables are overridden. SForum bridges `--ui-color-primary-*` and
  `--ui-primary` to the same runtime theme variables.

## Consequences

- Public frontend state may read `appearance.theme`.
- Adding a new preset requires updating backend validation, frontend theme
  choices, CSS variables, and translations.
- Admins can enter custom brand colors, but only through the validated
  `custom:#rrggbb` format.
