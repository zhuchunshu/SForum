# SForum 头像系统设计实施计划

## 设计总览

采用**分层回退**头像策略（用户上传头像优先 → 否则按全局默认策略），在 Options 系统新增 `avatar.*` 配置组，复用现有附件系统做上传，引入 `disintegration/imaging` 做压缩，新建前端用户资料页承载头像上传 UI。

### 头像解析优先级（运行时）
```
1. 用户已上传头像 (user_profiles.avatar_attachment_id → attachments.url)
2. 否则按 avatar.default_provider 全局设置：
   a. gravatar   → 按 email hash + avatar.gravatar_base_url 生成 URL
   b. identicon  → 服务端本地生成几何头像（基于用户名 hash）
   c. static     → avatar.default_static_url 静态图
   d. initials   → 前端 SFAvatar 现有的首字母兜底（不返回 URL，前端处理）
```

## 配置项设计（`avatar.*` Options 组）

| Option 名 | 默认值 | public | 说明 |
|---|---|---|---|
| `avatar.allow_upload` | `enabled` | 是 | 是否允许用户上传头像（总开关）|
| `avatar.default_provider` | `identicon` | 是 | 默认头像来源：gravatar/identicon/static/initials |
| `avatar.gravatar_base_url` | `https://www.gravatar.com/avatar/` | 是 | Gravatar 源地址（可自定义镜像）|
| `avatar.default_static_url` | （空）| 否 | static 类型默认头像图 URL |
| `avatar.max_size_kb` | `2048` | 是 | 用户上传头像原始大小上限（KB）|
| `avatar.max_dimension` | `512` | 否 | 上传头像最大边像素（超出将缩放）|
| `avatar.allow_gif` | `enabled` | 是 | 是否允许 GIF 头像（GIF 不压缩，仅校验大小）|
| `avatar.compress_enabled` | `enabled` | 是 | 是否启用上传压缩（转 webp/jpeg）|
| `avatar.target_dimension` | `256` | 否 | 压缩后目标尺寸（像素，正方形）|
| `avatar.compress_quality` | `85` | 否 | 压缩质量（jpeg 1-100）|

默认 `default_provider=identicon`（离线可用，符合"开箱即用"原则）。`gravatar` 需自定义源（国内访问问题），不作为默认。

## 后端改动

### 1. 新增 `avatar.*` 配置项（`apps/api/app/Models/Options/`）
- **`types.go`**：新增 `NameAvatar*` 常量（10 个），归到现有 NameXxx 常量块
- **`service.go` `optionDefinitions`**（约 line 101-206 末尾）：注册 10 个定义，全部 `managePermission: identity.PermissionSettingsManage`。`allow_upload`/`default_provider`/`gravatar_base_url`/`max_size_kb`/`allow_gif`/`compress_enabled` 设 `public: true`
- **`service.go` `normalizedDefaults()`**：加 10 个默认值
- **`service.go` `normalizeOptionValue()`**：加 10 个 case，复用现有 `normalizeEnabledOption`（开关）、`normalizeChoice`（枚举）、`normalizeBoundedInt`（数值）、`normalizeOptionalURL`（URL）。**这是最易漏的关键点**
- **`service.go` `coerceValueSet()`**：加同 10 个的兜底回退
- 新增 typed getter `AvatarOptions()`（参考 `PasswordPolicy()` service.go:319）供 Profile 服务消费

### 2. Profile 头像 URL 解析与校验（核心修复 + 新增）
当前 `Profile` service 只依赖 store，需扩展依赖以读取 options 和校验附件。

- **`app/Models/Profile/service.go`**：
  - `Service` 结构新增 `options *options.Service` 和 `attachments attachments.Store` 两个依赖字段
  - `NewService` 改为 `NewService(store, optionsSvc, attachmentStore)`；保留旧签名会破坏调用方，故同步改 Provider
  - 新增 `resolveAvatarURL(ctx, profile, email)` 方法：按优先级链返回最终 avatar URL + 类型
  - `GetPublicProfile` / `GetMyProfile` 在返回前调用 resolveAvatarURL，填充新字段 `AvatarURL`
- **`app/Models/Profile/types.go`**：
  - `Profile` 新增 `AvatarURL string`、`AvatarType string`（uploaded/gravatar/identicon/static/initials）字段
  - `PublicProfile` 透传这些字段
  - `UpdateProfileInput`/`NormalizeProfile` 不变
- **`app/Models/Profile/store.go`**：`Store` 接口新增 `GetAttachmentByID(ctx, id)` 方法（或直接依赖 `attachments.Store.GetByID`），用于校验归属
- **`app/Models/Profile/service.go` `UpdateMyProfile`**：新增头像上传校验（见下）：
  1. 若 `avatar.allow_upload = disabled` 且提交了新 avatarAttachmentId → 拒绝
  2. 校验 attachment 存在且 `owner_user_id == actor.ID`（防越权绑定他人附件）
  3. 校验 `content_type` 为 `image/*`
  4. 校验 `size_bytes <= avatar.max_size_kb * 1024`
  5. GIF 专项：若 `avatar.allow_gif = disabled` 且 contentType = image/gif → 拒绝

### 3. 头像压缩管线（`app/Support/Image/` 新模块）
- 新建 `app/Support/Image/process.go`：封装头像压缩逻辑
  - 函数 `ProcessAvatar(reader, opts AvatarProcessOptions) (processedBytes, contentType, error)`
  - 非图或 GIF（allow_gif 时）→ 原样透传
  - 启用压缩时：用 `imaging.Resize` 缩放到 `target_dimension`，编码为 webp（quality）
  - 复用 `disintegration/imaging`（纯 Go 无 cgo）
- **上传时机**：头像压缩发生在**头像绑定**时（PUT /profile），而非通用附件上传时。新增内部上传端点或复用通用上传后由 Profile service 二次处理。**决策**：在 Profile 服务内做——当 UpdateMyProfile 接收到新头像 attachment id 时，打开附件内容→压缩→写回新 attachment→绑定新 id。这样不污染通用上传路径
- **go.mod**：`go get github.com/disintegration/imaging`（需走代理）

### 4. Identicon 本地生成
- 新建 `app/Support/Avatar/identicon.go`：基于用户名/ID hash 生成本地 identicon PNG
- 库选型：`github.com/lafikl/identicon`（纯 Go，轻量）或自实现简单 5x5 几何块（避免依赖）。**决策**：先用轻量库 `lafikl/identicon`
- 暴露为：当 `avatar.default_provider=identicon` 且用户无头像时，`resolveAvatarURL` 返回一个内部路由 URL（如 `/api/v1/avatars/identicon/:hash.png`），新增对应 controller 路由实时生成

### 5. Gravatar URL 生成
- 新建 `app/Support/Avatar/gravatar.go`：按 email MD5 + `avatar.gravatar_base_url` 拼接，支持 size 参数
- 纯字符串拼接，无外部依赖

### 6. Provider 接线
- **`app/Providers/profile.go`**：`NewProfileProvider` 签名增加 `optionsService` 和 `attachmentsStore` 参数
- **`bootstrap/app.go`**（约 line 136）：传入 optionsService 和 attachmentStore

### 7. OpenAPI 契约（`contracts/openapi/`）

## 需要注意的边界
- **依赖注入破坏**：改 `profile.NewService` 签名会影响 bootstrap/app.go 和 Provider，需同步更新
- **normalizeOptionValue 的 default 分支会拒绝未注册 name**：avatar.* 的 case 必须三处（normalize/coerce/isValid）都加
- **Go 1.25.7**：imaging 库需兼容该版本（imaging 无 cgo，纯 Go，兼容性好）
- **国内代理**：`go get` 前需 `export https_proxy=http://127.0.0.1:7897 ...`
- **GIF 压缩**：多帧压缩复杂，GIF 一律原样透传（仅校验大小），符合"避免过度设计"原则
- **avatarAttachmentId 是数字主键 ID**：前端无法直接用，必须由后端解析成 url 返回（本次修复）
