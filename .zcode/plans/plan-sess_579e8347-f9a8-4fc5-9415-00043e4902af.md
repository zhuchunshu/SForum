# 修复 dev server 的 HMR reload（supervisor 代理补 WebSocket 转发）

## 根因
`bun run dev` 跑的是自定义 supervisor（`apps/web/scripts/dev-theme-runtime.mjs`），在 3000 端口起反向代理转发给临时端口的 nuxt dev 子进程。但共享的代理模块 `apps/web/scripts/theme-proxy.mjs` 只用 `http.createServer` 处理 HTTP 请求，**没有注册 `server.on('upgrade', ...)`**，导致 Nuxt/Vite HMR 的 WebSocket 握手被丢弃，浏览器拿不到热更新。改文件必须手动刷新，开发体验坏了。

## 修复点
单文件改动：`apps/web/scripts/theme-proxy.mjs`

### 1. 新增 `import net from 'node:net'`（当前只 import 了 `node:http`）
原始 socket 隧道需要 `net` 模块。

### 2. 在 `createThemeProxy` 内、`http.createServer` 之后（当前 theme-proxy.mjs:37 之后）注册 upgrade handler
新增一个模块私有函数 `forwardUpgrade(target, req, socket, head)`，并在 `createThemeProxy` 里 `server.on('upgrade', (req, socket, head) => ...)` 调用它。逻辑：

- 读 `activeTarget`（闭包变量，theme-proxy.mjs:27），为 `null` 时按你的选择 **直接 `socket.destroy()`** 关闭。
- 按 `target.socketPath` 分叉，与 `forwardRequest`（theme-proxy.mjs:82-84）完全一致的分支模式：
  - TCP：`net.connect({ host: target.host, port: target.port })`
  - Unix socket：`net.connect({ path: target.socketPath })`（生产 runtime.mjs 也用同一代理，顺带让生产环境的 app 级 WS 也能转发）
- upstream 连接建立后：把原始 HTTP 升级请求行 + headers（复用现有私有 `buildForwardHeaders`，theme-proxy.mjs:122）原样写入 upstream，然后 `socket ↔ upstream` 双向 pipe。
- 任一端 error/close 时 destroy 另一端，避免句柄泄漏（参照现有 `forwardRequest` 的 res.on('close') 兜底风格，theme-proxy.mjs:112-116）。
- upstream 连接失败时 `socket.destroy()`（浏览器 HMR client 自动退避重试，符合 Vite 行为）。

注释用中文，解释「为何不能复用 http.request」「为何要同时覆盖 TCP 与 unix socket」。

### 不改动的部分
- `dev-theme-runtime.mjs` / `runtime.mjs`：它们只调 `createThemeProxy`，upgrade 能力是代理内部补的，supervisor 无需感知。
- `nuxt.config.ts`：HMR 走默认同源 WS，不用改 Vite 配置。
- 蓝绿切换逻辑（`replaceTarget`）完全不动。

## 测试
在现有 `apps/web/tests/themeProxy.test.ts` 末尾新增一个 `describe` 块「theme-proxy: WebSocket upgrade 转发」，匹配现有风格（已 import `net`、`http`，复用 `freePort`）：

- **TCP 上游 WS 转发**：起一个带 `'upgrade'` handler 的假上游（收到升级后 echo 一个标记字节），通过代理发起 WS 握手，断言能收到 upstream 的回声、且 `x-forwarded-for` 被透传。
- **activeTarget 为 null 时连接被关闭**：不 setTarget，发起 WS 握手，断言 socket 被销毁（连接错误/关闭）。
- **Unix socket 上游 WS 转发**：起一个监听 `.sock` 的假上游，断言 WS 握手成功转发（覆盖生产路径）。

测试用 Node 原生 `net.connect` 手搓 WS 握手（发 `GET / HTTP/1.1\r\nUpgrade: websocket\r\n...`），不引第三方 ws 库（与现有测试零依赖风格一致）。
