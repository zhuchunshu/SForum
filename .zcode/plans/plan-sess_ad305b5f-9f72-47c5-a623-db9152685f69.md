# 评论系统 UI 改版方案（竖线树 + 折叠）

## 重要前提：真实根因（推翻初始假设）

调查后确认：**后端评论 API、OpenAPI 契约、帖子详情页都已完整存在并接入真实数据**。这次改版 **不动后端、不动契约、不动数据库**，全部是前端工作。

真正导致"乱、丑、树级显示有问题"的 4 个根因：

| # | 根因 | 位置 |
|---|---|---|
| 1 | **嵌套子评论只渲染一层，不递归** → 第 3 层及以下回复全部丢失 | `t/[topicID]/[topicSlug].vue:724-737` 只 `v-for` 了一层 `comment.children` |
| 2 | **`.sf-comment__children` 和 `.sf-comment__reply-to` CSS 完全没定义** → 引用块和子评论容器靠浏览器默认样式裸奔 | `sforum-components.css` grep 确认 0 条规则 |
| 3 | 详情页评论段 **22 处硬编码颜色**（`teal-300`/`slate-500`/`zinc-400` 等）→ 换主题不跟随 | `t/[topicID]/[topicSlug].vue` 评论操作按钮区 |
| 4 | **没有折叠交互** → 热门评论刷屏无法降噪；操作按钮（编辑/删除/举报）硬编码在详情页模板里，没复用 SFComment actions | 同上 |

## 决策记录（你已确认）

- 暂不做点赞（不扩契约）
- **子回复 ≥ 4 自动折叠**（任意层级；可手动展开/收起）
- 改动范围：**只改 `SFComment.vue` + 详情页评论段**（不动后端/契约/详情页其他部分/不全局去硬编码）

## 改动文件清单（3 个源文件 + 2 个 i18n + 1 个 demo）

### 1. `apps/web/app/components/SFComment.vue`（核心重写）
改成**真正的递归组件**，对齐已确认的 demo 设计：
- 新增 props：`comment?: ForumComment`（直接传整条评论，内部自取 author/content/replyTo/children）、保留 `depth`、新增 `collapsedThreshold?: number = 4`（折叠阈值）、`actions`、`replyTo`
- **折叠状态本地化**：用 `ref<boolean>` 管理，初始化时若 `children.length >= threshold` 则默认 `collapsed=true`
- 折叠按钮：chevron 图标 + 文案"收起" / "展开 N 条回复"（N = 递归统计后代总数）；折叠时 `v-show` 隐藏 children 容器
- **递归渲染**：在 `sf-comment__children` 容器内 `<SFComment v-for="child in children" :comment="child" :depth="depth+1" ...>` 调用自身（Vue 递归组件，靠组件 `name` 自引用）
- **保持向后兼容**：保留现有的纯展示 props（author/content/htmlContent/meta/avatar/authorLink/replyTo/actions）和默认 slot，让 `components.vue` 预览页不崩；新增 `comment` prop 时优先用它
- emit：保留 `action`，新增 `action-comment: [comment, value]`（带 comment 引用，方便父级定位）、`reply: [comment]`、`edit: [comment]`、`delete: [comment]`、`report: [comment]`、`toggle: [comment, collapsed]`

### 2. `apps/web/app/assets/css/sforum-components.css`（补齐 + 增强，约第 1385 行后插入）
全部用 `--sf-*` token，深浅色自动跟随：
- **`.sf-comment__reply-to`**：accent 色左边框 + accent-soft 底 + 圆角 + flex（icon + author + excerpt），补齐当前裸奔的引用块
- **`.sf-comment__children`**：margin-left/padding-left 对齐父头像中线 + `border-left: 2px solid var(--sf-border)` + `:hover > &` 只高亮当前层竖线（避免深层冒泡）
- **`.sf-comment--collapsed`** 修饰类：折叠态隐藏 children
- **`.sf-comment__toggle`**：折叠按钮样式（默认 fg-tertiary，折叠态 accent 色）
- 子评论分隔线：`sf-comment__children > .sf-comment + .sf-comment` 顶部细线
- 深色模式覆盖（文件末尾 `.dark .sf-comment__*` 段，约 2148 行附近）
- 头像尺寸按 depth 微调：根 `size=sm`，深层 `s28`（通过 `.sf-comment--deep .sf-avatar` 缩小，避免深层挤压）

### 3. `extensions/.../layer/app/pages/t/[topicID]/[topicSlug].vue`（评论段重构，约 639-746 行）
- **删除当前 639-746 的扁平渲染**，改为递归调用：
  ```vue
  <SFComment
    v-for="comment in comments"
    :comment="comment"
    :actions="commentActions(comment)"
    @reply="startReply"
    @edit="startEditComment"
    @delete="deleteComment"
    @report="(c) => openReportDialog({ type: 'comment', id: c.id })"
  />
  ```
- **操作按钮内聚进 SFComment**：编辑/删除/举报不再硬编码在详情页模板，改为由 `commentActions(comment)` 动态生成 actions 数组传给 SFComment；保留内联编辑器和回复编辑器（通过 SFComment 的具名 slot 或 `editingCommentId`/`replyingTo` 状态在递归组件内条件渲染）
- 内联编辑器/回复编辑器：由于递归组件化，编辑/回复编辑器需要随对应 comment 渲染——用 SFComment 的具名 slot（`#editor` / `#reply-editor`）配合父级 `editingCommentId`/`replyingTo` 状态在递归组件内条件渲染
- **移除该段 22 处硬编码颜色**（只限评论段，不动详情页其他部分）
- 折叠/展开文案、举报/编辑/删除按钮文案走 i18n

## 风险与缓解
- **风险 1**：递归组件 + 具名 slot 内联编辑器组合，Vue 递归 slot 传递较绕。**缓解**：编辑/回复编辑器用"父级状态 + SFComment 内 `v-if` 条件渲染 + 具名 slot 回传"，而非层层透传 slot；必要时把编辑器逻辑留在父级，SFComment 只负责展示+折叠+触发事件。
- **风险 2**：深层缩进挤压正文宽度。**缓解**：保留现有 `Math.min(depth, 4)` 封顶，深层头像缩小，且折叠交互天然减少深层展开场景。
- **风险 3**：向后兼容 `components.vue` 预览页。**缓解**：保留纯展示 props 和默认 slot，新增 `comment` prop 为可选优先项。

## 实施顺序
1. 先补 CSS（`.sf-comment__reply-to` / `.sf-comment__children` / 折叠样式）—— 立即改善现状，风险最低
2. 重写 `SFComment.vue` 为递归 + 折叠
3. 重构详情页评论段为递归调用 + 操作按钮内聚 + 去硬编码颜色
4. i18n + 测试 + 顺手修 parameters.yaml
