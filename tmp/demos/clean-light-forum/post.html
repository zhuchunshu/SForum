SForum 插件化架构演进：如何设计低耦合的 Extension 机制？

Chunshu 核心贡献者
发布于 2026-07-21 23:45 · 预计阅读 5 分钟

在开源论坛系统的演进过程中，如何既能保持核心框架（Core）的轻量与高效，又能赋予开发者无限的定制扩展能力？SForum 给出的答案是：Plugin-First（插件优先） 架构设计。

1. 核心契约与生命周期 (Core Extension Contracts)

Core 仅作为宿主框架存在，不硬编码特定厂商或商业逻辑。扩展包统一存放在 extensions/ 目录下，分为内置插件（Built-in）、可选插件（Optional）与开发套件。 

// Go 后端扩展挂载契约示例
type ExtensionProvider interface {
    Name() string
    Version() string
    OnBoot(app *bootstrap.Application) error
    RegisterRoutes(router *fiber.App)
}

2. 安全与信任边界 (Security & Trust Boundary)

“任何包含可执行代码的插件在安装/启用时，必须要求具有 exact-artifact 属性并经由 super_admin 显式确认。”

上传静态扩展包仅会进行校验、预览与保存，绝对不会直接执行未受信任的代码。只有在通过全局安全审计与信任确认后，路由替换表（Trusted Route Registry）才会允许插件注册对应的钩子。
