# 内容审核双工作台设计

## 背景

现有系统已经实现用户举报与后台举报处理页，但 `/moderation` 页面定义没有加入后台侧栏导航树，审核员只能从后台概览的快捷操作进入。举报列表只展示目标编号、举报原因、举报说明与审核备注，缺少原内容摘要、作者、所属主题或分类等判断上下文。

本次设计同时补齐内容预审能力，并将站点配置与日常审核拆成两个入口：管理员在后台配置审核策略，版主在前台审核工作台处理待发布内容和用户举报。

## 目标

- 后台提供独立的“审核管理”菜单，用于配置审核策略和查看全量审计记录。
- 前台提供独立的“审核工作台”入口，用于处理待发布内容和用户举报。
- 待办列表直接展示足够的内容上下文，减少仅凭目标编号判断或频繁跳页。
- 主题和评论支持发布前审核，并提供关闭、规则审核、全部审核三种模式。
- 后台管理与前台审核使用两个独立权限，不互相隐含。
- 保持 API 权限校验权威，待审内容不能通过公开接口、搜索或统计泄露。

## 非目标

- 不实现审核任务领取、指派、内部讨论或 SLA。
- 不在核心实现自定义敏感词库或机器学习风险评分。
- 不接入第三方审核平台。
- 不允许插件绕过核心内容状态、权限或公开查询策略。

## 方案选择

采用“队列分栏”方案。前台审核工作台包含“待发布”“用户举报”“处理记录”三个页签。相比混合单列表，该方案保持两类任务的动作语义清楚；相比完整任务流，它不引入当前不需要的协作模型，同时保留后续演进空间。

现有 Go 服务、Nuxt UI、PostgreSQL 和权限系统可以完整支持本功能，不增加第三方依赖。

## 权限与入口

### `moderation.manage`

- 控制后台“审核管理”页面的访问。
- 允许读取和修改审核模式、内置规则配置，并恢复推荐默认值。
- 允许查看全量审核审计记录，但不允许执行审核动作。

### `moderation.review`

- 控制前台“审核工作台”的入口和访问。
- 允许读取待发布队列、用户举报队列和处理记录。
- 允许执行通过、驳回、保留、隐藏和删除等审核动作。

两个权限必须分别授予。`moderation.manage` 不隐含 `moderation.review`，反之亦然。`super_admin` 继续按现有权限机制通过所有检查。

后台侧栏加入独立“审核管理”条目。前台登录用户导航仅在用户拥有 `moderation.review` 时显示“审核工作台”，并显示待处理总数徽标。路由守卫和隐藏入口只改善体验，API 仍执行最终权限校验。

## 审核策略

核心提供三种模式：

- `off`：主题和评论创建后直接公开。
- `rules`：仅命中启用规则的内容进入待发布队列。
- `all`：所有新主题和评论进入待发布队列。

为避免升级后意外阻断既有站点发布，存储层推荐默认值为 `off`。后台页面应将 `rules` 标为建议启用的日常运营方案，但不得未经管理员操作自动切换。

规则模式第一版提供两个可解释的内置条件：

- 新用户发布内容。新用户的判定阈值由审核配置保存，并带有安全默认值。
- 内容包含外部链接。站点自身域名不视为外部链接。

规则均可单独启用。未来敏感检测、信誉评分或供应商能力通过核心发布前过滤器和稳定事件扩展，不在核心内置敏感词引擎。

后台提供“一键恢复推荐默认值”。恢复操作只影响审核模式和规则参数，不影响权限分配、已有待办、处理记录或其他敏感状态，并在界面中明确说明保留范围。

## 内容状态与公开边界

主题状态增加 `pending` 与 `rejected`，评论状态增加 `pending` 与 `rejected`。创建服务在内容完成校验和安全渲染后解析审核策略，并将记录写为 `active` 或 `pending`。

- `pending` 和 `rejected` 内容不进入公开列表、公开详情、站点计数、活动流或搜索索引。
- 内容作者可以通过自己的内容状态接口看到待审或驳回状态及审核理由。
- 审核通过后状态变为 `active`，再更新公开统计并调度搜索索引。
- 驳回后状态变为 `rejected`，保留内容与审核结果供作者查看，不公开。
- 评论待审时不增加主题公开评论数，也不触发公开主题索引刷新。

状态流转和公开统计更新必须在服务边界内完成。插件只能通过受支持的过滤器提供审核信号，不能直接将待审内容改为公开。

## 数据模型

新增审核配置，保存模式、新用户阈值、外部链接规则开关等核心选项。配置解析遵循现有运行时选项模式，并提供默认解析和重置测试。

新增不可变审核决策记录，至少包含：

- 任务来源：`pre_publish` 或 `report`。
- 目标类型和目标 ID。
- 审核动作与结果。
- 审核员 ID、审核备注和处理时间。
- 触发规则快照或举报 ID。

现有 `moderation_reports` 继续保存每次用户举报。前台工作台按举报记录展示任务，第一版不做跨举报聚合；处理某条举报不会静默关闭同一内容的其他举报。若原内容已经被隐藏或删除，其他开放举报应显示目标当前状态，并允许审核员批量关闭或逐条确认，避免丢失举报审计信息。

## API 设计

后台审核管理 API 使用 `moderation.manage`：

- 读取审核配置与推荐默认值。
- 更新审核配置。
- 恢复推荐默认值。
- 查询全量审核决策记录。

前台审核工作台 API 使用 `moderation.review`：

- 获取待办数量汇总。
- 分页读取待发布内容。
- 分页读取用户举报。
- 分页读取处理记录。
- 获取单条任务的完整审核上下文。
- 提交预审决策或举报处置决策。

列表 DTO 由 API 整理，至少包含内容类型、标题或所属主题、正文摘要、作者、分类、提交时间、触发规则，以及举报场景下的举报人、原因和说明。详情 DTO 提供完整安全渲染内容；评论任务同时返回所属主题和必要的相邻回复上下文。前端不通过多组请求拼装基础展示信息。

审核 API 接受明确动作，不复用含义模糊的状态更新：

- 预审：`approve`、`reject`。
- 举报：`keep_and_close`、`hide_and_close`、`delete_and_close`。

所有接口同步更新模块化 OpenAPI 路径、模式、错误响应和权限说明。

## 动作与一致性

- `approve` 将待审内容公开，更新相关统计并在事务成功后调度索引。
- `reject` 保持内容不可公开并记录作者可见的理由。
- `keep_and_close` 保留原内容并关闭当前举报。
- `hide_and_close` 隐藏原内容并关闭当前举报。
- `delete_and_close` 删除原内容并关闭当前举报。

驳回、隐藏和删除必须填写审核备注；通过和保留内容时备注可选。举报处置在一个数据库事务内更新原内容、举报状态和审核决策记录，避免部分成功。

并发处理使用目标当前状态或版本进行条件更新。若任务已由其他审核员处理，API 返回稳定冲突原因；前端保留提示并刷新当前条目，不覆盖已有结果。

## 页面设计

### 后台审核管理

- 独立侧栏入口，不放入系统设置或论坛管理折叠组。
- 顶部展示当前审核模式和待办概况，但不提供审核动作。
- 配置区使用分段控制选择 `off`、`rules`、`all`，规则使用开关和数字输入。
- `rules` 标注为建议运营方案，`off` 说明兼容性默认行为。
- 保存和恢复默认值成功后显示符合当前主题色的成功 Toast，10 秒自动关闭。
- 错误保留在配置区域，不用自动关闭 Toast 替代阻断信息。
- 审计记录支持按结果、内容类型、审核员和时间筛选。

### 前台审核工作台

- 登录用户导航提供独立入口与待办徽标。
- 页面包含“待发布”“用户举报”“处理记录”三个页签。
- 顶部显示待发布数、待处理举报数和今日已处理数。
- 列表行展示正文摘要、作者、分类或所属主题、提交时间，以及触发规则或举报原因。
- 展开详情后显示完整内容上下文、审核备注和明确动作。
- 评论任务展示所属主题与必要的相邻回复，避免脱离语境审核。
- 桌面端使用紧凑列表加展开详情；移动端使用单列详情，动作区不固定覆盖正文。
- 操作成功显示主题适配的成功 Toast 并从当前待办移除；阻断错误保持可见。

### 作者反馈

创建命中审核策略的内容时，成功响应明确返回待审状态。前端显示“内容已提交审核”，而不是误报发布成功。作者可查看待审状态；内容被驳回时可查看处理结果与理由。普通访客无法访问这些状态和内容。

## 错误处理

- 无权限访问返回稳定的 403 原因，页面不渲染敏感队列数据。
- 任务不存在或目标已永久删除时返回明确状态，不伪装成空成功。
- 并发冲突返回 409 和稳定原因，客户端刷新对应任务。
- 配置校验错误返回字段级信息；保存失败保留表单输入。
- 搜索索引调度失败不回滚已经提交的审核事务，沿用现有可靠队列和重试机制，并记录可观测错误。

## 测试与验证

后端测试覆盖：

- `moderation.manage` 与 `moderation.review` 分别允许和拒绝对应接口。
- 两个权限互不隐含，`super_admin` 行为保持一致。
- `off`、`rules`、`all` 三种模式对主题和评论创建的状态解析。
- 新用户与外部链接规则命中和未命中。
- 待审、驳回内容不进入公开查询、统计和搜索索引。
- 通过后公开、统计和索引调度正确。
- 举报处置事务与审核决策记录一致。
- 必填审核备注、并发冲突和重复处理。
- 默认值解析与一键恢复行为。

前端测试和浏览器验证覆盖：

- 后台与前台入口按各自权限显示或隐藏。
- 待办徽标、三个页签、筛选和分页。
- 主题与评论任务的信息层级和上下文展示。
- 每类审核动作的确认、成功 Toast、错误与冲突刷新。
- 作者提交待审内容后的反馈和驳回理由展示。
- 桌面与移动视口下无重叠、裁切或动作遮挡。
- 页面身份、非空渲染、无框架错误覆盖层、控制台健康和至少一条完整审核交互。

完成实现后运行 Go 测试、Nuxt 类型检查、OpenAPI 引用校验、相关仓库验证脚本，并通过项目现有浏览器开发工具对运行中的前后端执行可视化验收。
