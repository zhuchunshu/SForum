# 默认主题三栏高密度首页设计

## 背景与目标

当前 SForum 默认主题首页已经有三栏雏形，但整体仍偏卡片堆叠：左侧导航是局部辅助栏，中间话题流被卡片外框和摘要占用较多空间，右侧信息块较重。用户明确反馈“默认主题实在太丑”，并希望参考 linux.do 的三栏信息组织：左侧侧边栏始终显示分类、标签等菜单信息，中间是大的内容区域。

本设计目标是将默认主题首页调整为更像成熟论坛的高密度工作台：打开首页即可扫话题、切分类/标签、查看回复/浏览/最后活动。默认主题应保持克制、清晰、可扩展，不做营销式首页，不引入新依赖，也不复制特定站点品牌风格。

## 已确认方向

通过 visual companion 展示了三个方向：

- A. Linux.do 式高密度
- B. 新手友好社区门户
- C. 阅读优先控制台

用户选择并确认 A 方向。最终方案采用“高密度三栏默认主题”：

- 左侧：常驻 sticky 导航栏，包含首页/热门/精华/关注入口、分类列表、标签列表。
- 中间：主内容区采用高密度话题列表/话题表，而不是大卡片流。
- 右侧：轻量辅助栏，包含登录/用户状态、热帖、站点统计、运行状态等信息。
- 移动端：主内容优先，左侧信息折叠为顶部分类/标签入口，右栏下沉或隐藏。

## 范围

### 首版包含

- 调整默认主题首页布局，目标桌面结构约为 `240px / minmax(0, 1fr) / 262px`。
- 左侧栏在桌面端 sticky 常驻，突出分类和标签入口。
- 中间话题列表改为更紧凑的话题表体验，展示标题、分类/标签、作者/时间、回复数、浏览数和最后活动信息。
- 右侧栏保留轻量状态模块，不抢主内容注意力。
- 保留现有深浅色模式、配色预设、国际化、SEO、权限判断和 API 数据来源。
- 增加或调整针对首页结构的测试，覆盖三栏类名、列表行结构和响应式入口。

### 首版不包含

- 不新增后端接口。
- 不实现真正的热门、精华、关注排序逻辑；现有不可用 tab 保持禁用或明确不可用状态。
- 不新增第三方 UI 或图标依赖。
- 不改后台管理 UI。
- 不重新设计帖子详情页或评论树，除非首页列表组件复用需要做兼容性微调。

## 信息架构

### 顶部导航

默认主题顶部导航继续由 `SFNavbar` 承担，保留站点名、首页入口、发帖入口、语言切换、深浅色切换和用户菜单。首页重设计不应把发帖权限逻辑搬入页面局部；仍由现有权限判断决定是否显示发帖入口。

### 左侧常驻栏

左侧栏成为默认首页的信息导航中心：

- 主导航：全部讨论、热门、精华、关注。
- 分类：从 `categoryGroups` 展平后的分类列表，显示分类颜色点和主题数。
- 标签：显示 active 标签，点击后筛选主题。

左侧栏在 `lg` 以上显示为 sticky 栏。`md` 尺寸下可优先保留中间和右侧；移动端不显示常驻栏，改为中间区域顶部的分类/标签筛选入口。

### 中间内容区

中间内容区是首页视觉重心：

- 顶部工具栏包含页面标题、排序 tab、搜索框和当前筛选状态。
- 主题列表使用单个容器和行分割线，不使用每条主题独立大卡片。
- 每行主题优先显示标题，其次显示分类/标签、作者、最后活动时间。
- 右侧统计列显示回复数、浏览数和最后活动用户/时间，保证桌面端快速扫描。
- 对窄屏做列收缩：移动端保留标题、分类/标签、回复数或最后活动摘要，隐藏次要统计列。

### 右侧辅助栏

右侧栏只提供辅助上下文：

- 未登录时：简短欢迎、登录/注册入口。
- 已登录时：用户状态和快速动作。
- 热门讨论：基于当前已加载主题的评论数排序，作为首版轻量近似。
- 站点统计：复用现有分类/主题统计。

右侧栏不得成为复杂运营卡片集合，避免稀释主内容区。

## 组件与文件边界

主要改动集中在：

- `extensions/builtin/themes/sforum-default/layer/app/pages/index.vue`
- `apps/web/app/components/SFFeedRow.vue`
- `apps/web/app/assets/css/sforum-components.css`
- `extensions/builtin/themes/sforum-default/layer/app/assets/css/sforum-theme.css`

建议把首页内重复的 class 组合收敛为语义化 class，例如：

- `.sforum-home`
- `.sforum-home__layout`
- `.sforum-home__left`
- `.sforum-home__main`
- `.sforum-home__right`
- `.sforum-topic-table`
- `.sforum-topic-row`

`SFFeedRow` 继续作为可复用主题行组件，但应支持更接近话题表的布局。若现有属性不足，可以在不破坏现有调用的前提下补充可选属性，例如 `lastActivityLabel`、`categoryLabel` 或 `tags`。不要为了首页临时复制一套难维护的行模板。

## 数据流

数据来源沿用现有实现：

- `forumApi.listCategoryGroups()` 获取分类组和分类。
- `forumApi.listTags()` 获取标签，并过滤 active 标签。
- 无搜索关键词时调用 `forumApi.listTopics()`。
- 有搜索关键词时调用 `forumApi.searchTopics()`。

筛选状态仍由首页本地状态管理：

- `searchQuery`
- `selectedCategorySlug`
- `selectedTagSlug`
- `currentTab`
- `currentPage`

切换搜索、分类或标签时重置到第一页。不可用排序 tab 不触发后端请求。

## 权限与安全

首页读取公开论坛数据，不新增权限边界。发帖入口、关注入口或用户相关模块必须继续尊重现有登录状态和权限判断：

- 发帖入口仍依赖 `topic.create`。
- 未登录用户不显示需要登录后才有意义的私有状态。
- 前端隐藏或禁用控件只是体验辅助，不能被视为 API 授权。

本设计不新增 unsafe mutation，不改变现有 API policy。

## 响应式设计

桌面端：

- `lg` 以上显示完整三栏。
- 左栏 sticky 常驻；右栏在 `lg` 以上也使用 sticky 顶部对齐，但内容长度应控制在首屏附近，避免滚动陷阱。
- 中间列表保持最大可读宽度，避免标题列被左右栏挤压。

平板端：

- 优先保留中间内容和右侧辅助栏。
- 左侧分类/标签入口改为主内容顶部的紧凑筛选区。

移动端：

- 单栏主内容。
- 分类、标签、排序和搜索集中在列表顶部。
- 主题行隐藏次要统计列，避免文字挤压和横向滚动。

## 状态处理

加载状态：

- 继续使用 `SFSkeleton`，但 skeleton 应匹配紧凑行布局，而不是大卡片布局。

空状态：

- 保留 `SFEmptyState`。
- 当无内容是筛选导致时，文案应提示清除筛选或搜索关键词。
- 当社区内容少时，可以借鉴 B 方向，在右栏或空状态中提供更友好的新手引导，但不改变主列表结构。

错误状态：

- 本设计不新增错误通路。若现有 API 调用失败，应沿用项目已有 Nuxt/useAsyncData 错误处理模式，不用 toast 替代阻塞状态。

## 视觉系统

整体风格：

- 克制、清楚、高密度、论坛产品感。
- 背景继续使用 `--sf-surface`。
- 主体容器和行分割线使用轻边框，减少厚重阴影。
- 卡片圆角不超过现有 `8px` 到 `10px` 风格，避免大圆角和过度装饰。
- 保留当前 Pine Teal 配色预设和暗色变量。

图标：

- 继续使用现有 Nuxt Icon / Lucide 图标。
- 不使用 emoji 作为图标或状态标记。

排版：

- 主题标题使用较高权重和紧凑行高。
- 统计、标签、时间等次级信息用更低对比度，但必须满足可读性。
- 避免超小字号；侧栏正文不低于 12px，主题行关键文本不低于 14px。

## 测试与验证

自动化验证：

- 运行 `bun test` 中与首页、论坛分类/标签、组件结构相关的测试。
- 运行 `bun run typecheck`。

视觉验证：

- 启动现有 web 开发服务或使用用户已运行的端口 3000。
- 验证桌面、平板、移动端首屏。
- 检查深色模式。
- 检查搜索、分类筛选、标签筛选和分页。
- 检查未登录与已登录状态的右栏差异。

回归注意：

- 不要杀掉用户自己占用的 3000 端口。
- 工作区已有未提交改动时，只合并与本任务必要的文件，不能回滚用户改动。

## 后续计划入口

用户确认本 spec 后，进入 implementation plan。计划应把实现拆成以下阶段：

1. 首页结构和语义 class 收敛。
2. `SFFeedRow` 高密度行组件调整。
3. 主题 CSS 和深色模式适配。
4. 响应式行为和状态样式。
5. 测试、typecheck、浏览器视觉验证。
