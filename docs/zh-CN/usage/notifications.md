# 通知

[<- 使用说明](./README.md)

Notification Platform V2 由 Core 持有站内信和投递策略，可信扩展只能声明
通知类型或提供外部渠道。

## 用户设置

在 `/settings/notifications` 查看每种通知类型及其可用渠道。控制项可能是：

- **跟随站点推荐**：继承管理员当前推荐值；
- **启用**或**停用**：管理员允许覆盖时，保存明确的个人偏好；
- **锁定/不可用**：该类型为必需通知、已被管理员关闭，或所选提供方不可用。

恢复推荐设置只会删除个人覆盖，不会改变站点策略或提供方秘密。外部渠道不可用时，
站内信筛选和未读数仍可使用。

## 浏览器推送

Web Push 区域会显示浏览器支持与权限状态。启用后，SForum 注册 Host 自有的
`/_sforum/notifications/sw.js`，作用域固定为 `/_sforum/notifications/`。
该 Service Worker 只显示受限通知并打开同源通知页，不导入插件代码，也不接受
任意动作或外部 URL。

API 只把订阅绑定到当前登录用户。设置页和投递记录会隐藏 endpoint 与浏览器密钥。
撤销浏览器权限或订阅不会关闭站内信。

## 管理员设置

拥有 `settings.notifications.manage` 的管理员可在
`/control-panel/settings/notifications`：

- 启停类型/渠道，设置推荐值，并控制用户能否覆盖；
- 查看 Core/扩展归属；新插件类型默认关闭，等待管理员审核；
- 选择精确 Web Push 提供方制品，向自己发送测试，并查看脱敏投递健康；
- 恢复 Host 推荐值，同时保留 VAPID 和其他提供方秘密。

邮件传输与邮件历史仍归 Mail 管理，既有邮件 API 和 `mail_deliveries` 保持兼容；
Web Push 使用通用渠道投递账本。提供方失败会在账本中可见，但不会阻止站内信。

## 排障

- Web Push 不可用时，依次检查浏览器支持、通知权限、有效订阅、已选择的提供方和
  VAPID 密钥；
- 策略保存发生冲突时先刷新页面；通知设置使用乐观 revision；
- 已隐藏或删除的主题/评论会显示为不可用，不会泄露 actor、摘要、审核备注或路由。
